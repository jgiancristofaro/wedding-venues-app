# Decisions

Ambiguities resolved during the build, with reasoning.

1. **Supabase** for backend (Postgres + RLS, Auth with Google & magic link, private Storage, Deno Edge Functions) — all on the free tier, and RLS lets the static Pages site talk to the DB directly with only the anon key. Firebase was the main alternative; Postgres + SQL RLS policies are easier to test (we run them against real Postgres in CI).
2. **Demo mode backend.** When no Supabase config is present at build time the app uses a browser-only backend (localStorage + IndexedDB, simulated sign-in, per-user namespacing). This makes the Pages URL useful on day one and lets Playwright run hermetically. Cloud and demo share one `Backend` interface.
3. **Pricing stored as a JSONB document** (`pricing` column) on `global_venues` / `user_venues` rather than normalized rule tables. Rules are always read/written as a unit, are validated by `sanitizePricing` on every load, and copying a global venue into a private library is one row. Same reasoning for **field provenance** (`field_provenance` JSONB on `user_venues`, keyed by field): atomic with the value it describes and covered by the row's RLS.
4. **Rate model:** every pricing component holds a list of rates, each with optional conditions (days, months, season, specific dates, time slot, guest range). The most specific matching rate wins (dates > day/month > season > guest range > default). This one mechanism covers day-of-week, seasonal, date overrides and guest-tiered per-person pricing.
5. **Per-person components are alternative packages** (only one applies; default = cheapest, range spans all). Additive per-guest charges (bar, cake cutting, corkage) are `addon`s with `unit: per_person`.
6. **Minimum-spend semantics:** if the minimum excludes service & tax, F&B is topped up to the minimum _before_ charges (service and tax then apply to the minimum). If it includes service and/or tax, the top-up is computed after charges and is final (taxed only if the minimum excludes tax).
7. **Missing data defaults (honest, visible):** tax 8.875% (NYC, editable per venue); unknown service charge for in-house F&B → 20% base (18–24% range), flagged _Partial_; no catering pricing → outside catering estimate $165/guest ($125–$225 range), flagged _Rough_; only a minimum known → spend = minimum (high case +20%). Unknown day → Saturday; unknown month → June; ranges span Fri/Sat/Sun and all seasons. Tax applies to mandatory service charges by default (NY practice) — toggleable.
8. **Confidence:** Unknown (no rules), Rough (any major gap: estimated catering, guest count beyond tiers, missing buyout/package rate), Partial (minor gaps: assumed service charge, missing day rate, stale pricing), Complete otherwise. Pricing older than 18 months is flagged "may be outdated".
9. **Heart = copy with snapshot.** Saving a library venue copies its fields + pricing and stores a `global_snapshot`. Library updates are diffed field-by-field against the snapshot; the user accepts or keeps theirs per field. Edits to a library venue first create the private copy ("Save a private copy to edit").
10. **Admins** are listed in `public.app_admins` (enforced by RLS via `is_admin()`); `ADMIN_EMAILS` (Edge Functions) and `VITE_ADMIN_EMAILS` (UI hint) mirror it. Admin-created/imported library venues start unpublished and require source, license/permission note and pricing-as-of date.
11. **SheetJS** comes from `@e965/xlsx` 0.20.3 (a verbatim npm mirror of SheetJS CE): the official CDN tarball wasn't reachable from the build environment and the npm `xlsx` package is stuck on 0.18.5 (known CVEs when parsing untrusted files).
12. **Geocoding:** Nominatim (OSM). Cloud mode goes through the `geocode` Edge Function (identifying User-Agent, ≤1 req/s, shared `geocode_cache` table); demo mode calls Nominatim from the browser with a 1 req/s queue and localStorage cache. Import geocodes after saving so imports never block on it.
13. **Photos:** no stock photography. Sample venues use deterministic SVG illustrations (clearly captioned). Photos extracted from documents/uploads are downscaled JPEG data URLs stored with the venue (simple and private; see limitations).
14. **Routing:** `BrowserRouter` with `basename = BASE_URL` and `404.html` = `index.html` for GitHub Pages deep links. Supabase auth uses PKCE with redirect back to the site root; the attempted action (e.g. heart) is kept in `sessionStorage` and replayed after sign-in.
15. **Offline:** reads are cached per user in localStorage; failed writes due to network are queued in an outbox and replayed on reconnect; an offline banner explains it.
16. **AI:** provider adapter interface (`CallModel`) with Anthropic as default; structured output via JSON schema + our own validator + one repair retry; per-user daily quotas, page caps, hash cache, usage log. Magic Fill only proposes values for empty fields, each with a source URL, and the user accepts per field. Default model `claude-opus-5-5`, configurable with `AI_MODEL`.
17. **Spreadsheet imports run client-side** as a background job (the user keeps browsing; a progress banner shows status and the job is saved to `import_jobs`). Files never leave the browser except documents that the user attaches.
18. **Multiple sheets:** the importer ranks sheets by how venue-list-like they are and lets you pick a sheet; import another sheet by repeating the flow.
19. **Theme toggle** is in the header on tablet/desktop and in Settings (hidden in the 375px header to avoid overflow); default follows the OS.
